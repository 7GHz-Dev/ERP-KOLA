# KOLA ERP v2 — Next.js + Postgres

โปรเจกต์ใหม่ที่เขียนแทนระบบเดิมบน Google Apps Script + Sheets

ระบบเดิมยังอยู่ครบที่โฟลเดอร์แม่ ใช้งานได้ตามปกติ **ตัวนี้พัฒนาคู่ขนานไปก่อน** แล้วค่อยสลับเมื่อพร้อม

## ทำไมถึงย้าย

วัดจากโค้ดจริงของระบบเดิม ไม่ใช่ความรู้สึก:

| จุดที่ช้า | ระบบเดิม | v2 |
|---|---|---|
| ค้นหางาน 1 รายการ | `getTable_()` อ่าน**ทุกแถว**ของชีตเข้าหน่วยความจำแล้ว `filter` | `WHERE` + index |
| เปิดหน้ารายการ | `getBootstrapData` ดึง JOBS + FILES + APPROVALS + CUSTOMS ทั้งตาราง | query เฉพาะที่ใช้ |
| ตรวจ token ทุก request | ไล่อ่านทั้งชีต `_SESSIONS` | unique index บน `token_hash` |
| เขียน 1 แถว | `LockService` ล็อกทั้งสคริปต์ ทุกคนรอคิวกัน | transaction ระดับแถว |
| แก้โค้ด 1 บรรทัด | `clasp push` + `clasp deploy` แล้วรอ Google | hot reload ทันที |

ต้นตอที่แท้จริงคือ **Sheets ไม่มี index** ทุกคำถามจึงกลายเป็นการสแกนทั้งตาราง ยิ่งงานเยอะยิ่งช้าแบบทวีคูณ
ส่วน `LockService` ทำให้การเขียนพร้อมกันกลายเป็นคิวเรียงเดี่ยว

## สิ่งที่เปลี่ยนจากเดิมโดยตั้งใจ

**Master data รวมเป็นตารางเดียว** — เดิมแยก 11 ชีต (`MD_SHIPPERS`, `MD_PORTS`, …) ที่มีคอลัมน์เกือบเหมือนกัน
รวมเป็น `master_records` แยกด้วยคอลัมน์ `type` เพิ่มชนิดใหม่ไม่ต้องสร้างตาราง

**Automation Hub ยุบเข้ามา** — เดิมเป็น Apps Script อีกโปรเจกต์เพราะ Sheets แชร์ข้ามโปรเจกต์ลำบาก
ตอนนี้เป็นตาราง `automation_tasks` ในฐานเดียวกัน Python เรียก REST endpoint ของ v2 ได้ตรง ๆ **ลดระบบที่ต้องดูแลจาก 2 เหลือ 1**

**ไฟล์ย้ายไป Supabase Storage** — คอลัมน์ `storage_key` แทน `driveFileId`
เก็บ `legacy_drive_file_id` ไว้ด้วยเพื่อให้ไฟล์เก่ายังตามกลับไปหาได้ระหว่างช่วงเปลี่ยนผ่าน

**คง id เดิมทุกแถว** — `JOB-xxxx`, `USR-xxxx` ใช้ต่อได้ ย้ายข้อมูลเข้ามาแล้วความสัมพันธ์ไม่พัง

**ใส่ index ในจุดที่ระบบเดิมต้องสแกนเอง** — สถานะงาน, ไฟล์ปัจจุบันของแต่ละหมวด, คิวอนุมัติ, `token_hash`

### รหัสผ่านเดิมใช้ต่อได้

ผู้ใช้ที่ย้ายมาล็อกอินด้วยรหัสเดิมได้ทันที ระบบตรวจด้วยสูตรเดิม (SHA-256 วน 600 รอบ + pepper)
แล้ว**อัปเกรดเป็น scrypt ให้เองตอนล็อกอินสำเร็จครั้งแรก** ผู้ใช้ไม่ต้องทำอะไร

ต้องคัดลอก `PASSWORD_PEPPER` จาก Script Properties ของโปรเจกต์เดิมมาใส่ `.env.local` ด้วยมือ
**ไม่มีช่องทางดึงผ่าน API โดยตั้งใจ** ความลับจึงไม่เคยวิ่งผ่านเครือข่าย

ตรวจว่าสูตรตรงกันจริง:

```bash
npx tsx scripts/verify-legacy-hash.ts
```

เทียบผลกับ `passwordHash_()` ตัวจริงที่โหลดจากไฟล์ `.gs` ครอบคลุมรหัสภาษาไทยและรหัสที่มีอักขระ `|`
ซึ่งเป็นตัวคั่นในสูตร — เคสที่พังง่ายที่สุด

## แผนย้าย — ทำเป็นขั้น ไม่ตัดของเดิมทิ้ง

1. **สร้างฐานข้อมูล** — `db:push` ให้ schema ขึ้นครบ
2. **ย้ายข้อมูล** — ดึงจากระบบเดิมผ่าน API ที่มีอยู่แล้ว เข้า Postgres (`npm run migrate:sheets`)
3. **ย้ายไฟล์** — โหลดจาก Drive เข้า Supabase Storage แล้วเติม `storage_key`
4. **เขียนหน้าจอทีละ role** — เริ่มที่ PAINT งานคงค้าง เพราะใช้บ่อยและช้าที่สุด
5. **รันคู่ขนาน** — v2 อ่านอย่างเดียวก่อน เทียบผลกับของเดิม
6. **สลับ** — เมื่อครบทุกหน้าแล้วค่อยหยุดใช้ระบบเดิม

**ระบบเดิมยังทำงานได้ตลอดทุกขั้น** ไม่มีจังหวะที่ต้องหยุดใช้งานเพื่อรอ v2


## กติกาสองข้อที่ห้ามพลาดซ้ำ

**ห้ามครอบตารางด้วยฟอร์มค้นหา** — HTML ไม่ยอมให้ `<form>` ซ้อน `<form>` เบราว์เซอร์จะทิ้ง
แท็กฟอร์มด้านในทั้งหมดเงียบ ๆ ปุ่มในแถวจึงกลายเป็นปุ่มส่งฟอร์มค้นหา กดแล้วหน้าโหลดใหม่
โดยไม่มีอะไรเกิดขึ้น ซึ่งดูเหมือนระบบพังแต่ไม่มี error ให้เห็น
`JobTable` จึงวางฟอร์มค้นหาไว้นอกตาราง แล้วให้ช่องค้นหาผูกกลับด้วย `form="..."`
`scripts/test-actions.ts` จับกรณีนี้ได้ เพราะมันยิงฟอร์มแบบเดียวกับเบราว์เซอร์จริง

**คำสั่งทุกตัวต้องห่อด้วย `runAction`** — ถ้า server action โยน error ออกมาตรง ๆ
ผู้ใช้จะเจอหน้า *500 Internal Server Error* เปล่า ๆ ซึ่งไม่บอกว่าต้องแก้อะไร
`runAction` ใน `src/lib/actions/common.ts` จับข้อความไว้แล้วพากลับหน้าเดิมพร้อม `?err=`
ให้แถบ `ActionAlert` แสดงผล — เป็น POST-redirect-GET ด้วย กดรีเฟรชซ้ำแล้วไม่ทำรายการซ้ำ

## อีกสองกติกาที่เจอตอนไล่ปัญหา

**ฟอร์มค้นหาต้องมีปุ่ม submit จริง** — HTML กำหนดว่า ถ้าฟอร์มไม่มีปุ่ม submit
และมีช่องข้อความมากกว่าหนึ่งช่อง การกด Enter จะไม่ส่งฟอร์มเลย
ตารางมีช่องค้นหาหลายช่องอยู่แล้ว ปุ่ม "ค้นหา" จึงเป็นของจำเป็น ไม่ใช่ของประดับ

**เทสต์ต้องหาฟอร์มด้วยรหัส action ไม่ใช่ข้อความบนปุ่ม** — หน้าที่ใหญ่พอ React จะทยอย
ส่ง HTML ปุ่มบางอันมาทีหลังเป็นก้อนแยก อยู่คนละที่กับฟอร์มใน HTML ดิบ
(เบราว์เซอร์ย้ายเข้าที่ให้เองด้วยสคริปต์ inline) เทสต์จึงอ่านรหัส action จาก
`.next/server/server-reference-manifest.json` แล้วจับคู่กับฟอร์มแทน

## บทเรียนเรื่องไฟล์ PDF ของสายเรือ

**`ignoreEncryption: true` ไม่ใช่การถอดรหัส** — Arrival Notice จากสายเรือหลายใบถูกล็อกไว้
ไม่ให้แก้ไข (เข้ารหัสโดยที่รหัสผ่านฝั่งผู้อ่านเป็นค่าว่าง) `pdf-lib` ตัวปกติเปิดไฟล์แบบนี้ได้
ด้วย `ignoreEncryption` และคัดลอกหน้าออกมาได้ครบจำนวน **แต่เนื้อในหายหมดกลายเป็นหน้าขาว**
ซึ่งดูเผิน ๆ เหมือนรวมสำเร็จ

โปรเจกต์นี้จึงใช้ `@cantoo/pdf-lib` (fork ที่ยังเป็น MIT) แล้วโหลดด้วย `{ password: '' }`
ซึ่งถอดรหัสจริง วัดด้วย pdfjs แล้วตัวอักษรต่อหน้าเท่าต้นฉบับเป๊ะ
`scripts/test-flow.ts` เอาไฟล์สายเรือของจริงมาทดสอบและตรวจว่าไม่มีหน้าไหนว่าง

## ฟอนต์ไทยสำหรับออกคำร้อง

`assets/fonts/Sarabun-Regular.ttf` และ `Sarabun-Bold.ttf` ต้องมีอยู่ ไม่งั้นออกคำร้องไม่ได้
ฟอนต์มาตรฐานของ PDF ไม่มีตัวอักษรไทยเลย (Sarabun เป็นสัญญาอนุญาต OFL แจกจ่ายพร้อมโปรแกรมได้)

**ห้ามเปิด subset ของฟอนต์** — ตัวตัด subset ใน fontkit พังกับตาราง glyph ของฟอนต์ไทยตัวนี้
(`Cannot read properties of undefined (reading 'pos')`) จึงฝังทั้งไฟล์ ใหญ่ขึ้นราว 160 KB ต่อฉบับ

ภาษาไทยไม่มีช่องว่างระหว่างคำ ตัดขึ้นบรรทัดใหม่เองไม่ได้ ทุกบรรทัดจึงวัดความกว้างจริง
แล้วย่อขนาดอักษรลงให้พอดีแทน ดีกว่าปล่อยล้นขอบหรือตัดข้อความทิ้ง
