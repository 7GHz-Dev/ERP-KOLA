# อ่าน AN / BL แบบหลายชั้น

ระบบอ่านเอกสารใช้หลายวิธีต่อกันเป็นชั้น ไม่ใช่เลือกวิธีเดียว
เพราะวัดกับเอกสารจริงแล้วพบว่า **ไม่มีวิธีไหนชนะทุกกรณี**

หลักที่ห้ามละเมิด: **เติมค่าผิดแย่กว่าปล่อยว่าง**
ผู้ใช้กดบันทึกเร็วและมักไม่ทันสังเกตค่าที่ระบบเติมให้

---

## ทำไมต้องหลายชั้น

วัดกับเอกสารจริง 9 ใบ (45 ช่องที่ตรวจเฉลยด้วยตาแล้ว):

วัดจริงกับเอกสาร 9 ใบ · 45 ช่องที่ตรวจเฉลยด้วยตาแล้ว (`npm run try:ocr`)

| วิธี | คะแนนรวม | ใบ PDF ปกติ | ใบสแกน | ค่าใช้จ่าย |
| --- | --- | --- | --- | --- |
| กรอบ + regex | 16/45 = 36% | **16/16 = 100%** | 0/29 = 0% | ฟรี |
| OCR | 24/45 = 53% | แย่ลงกว่ากรอบ¹ | อ่านได้บางส่วน | ฟรี |
| **AI** | **45/45 = 100%** | 16/16 | **29/29** | ~0.83 บาท/ใบ |

¹ OCR คืนมาแค่ข้อความ **ไม่มีพิกัด** ระบบกรอบจึงใช้กับผลของ OCR ไม่ได้
ต้องพึ่งตัวอ่าน regex ล้วน ซึ่งแม่นน้อยกว่ากรอบ

### เรื่องที่สำคัญกว่าคะแนน — OCR ให้ค่าผิดที่ดูน่าเชื่อ

| ช่อง | OCR อ่านได้ | ค่าจริง |
| --- | --- | --- |
| น้ำหนัก | `157000` | `22820` |
| เที่ยวเรือ | `6265` | `626S` |
| เลข BL | `NSSLKNILC2600020` | `NSSLKNILC26Q0020` (Q กลายเป็น 0) |
| ชื่อเรือ | `DEPARTURE AND INVOICE ISSUANCE` | `MAERSK NARVIK` |

ค่าพวกนี้ผ่านตาคนที่กดบันทึกเร็วได้สบาย แล้วหลุดไปถึงจดหมายที่ยื่นสายเรือ
**นี่คือเหตุผลที่ AI มาก่อน OCR** ไม่ใช่เพราะคะแนนอย่างเดียว

**ข้อสรุป** — ใบปกติกรอบทำได้ 100% และฟรี จึงยังเป็นด่านแรกเสมอ
ช่องว่างอยู่ที่ใบสแกน ซึ่ง AI อ่านได้ครบ 100% ในราคาที่ยอมรับได้

---

## ลำดับชั้น

```
เลือกไฟล์
  │
  ├─ ชั้น 1  กรอบที่ตั้งไว้           ในเบราว์เซอร์ · ฟรี · ไฟล์ไม่ออกจากเครื่อง
  ├─ ชั้น 2  ตัวอ่านอัตโนมัติ (regex)  เติมช่องที่กรอบไม่ได้กำหนด
  │
  │   ครบช่องสำคัญแล้ว → จบ ไม่เรียกชั้นถัดไป (ใบปกติจบตรงนี้เสมอ)
  │
  ├─ ชั้น 3  AI                      ~0.83 บาท/ใบ · แม่น 100% · อ่านไฟล์สแกนได้
  └─ ชั้น 4  OCR                     ฟรี · ตาข่ายรับท้ายเมื่อ AI ใช้ไม่ได้
```

"ช่องสำคัญ" = `blNo · vessel · voyage · eta · grossWeight · containers`
(`KEY_FIELDS` ใน `src/lib/read-layers.ts`) ครบแล้วไม่เรียกชั้นที่เสียเงิน
ช่องอื่นที่ยังว่างให้คนกรอกเองเร็วกว่ารอ

### กติกาที่สำคัญที่สุด

**ชั้นหลังเติมได้เฉพาะช่องที่ยังว่าง ห้ามทับค่าของชั้นก่อน**

ชั้นแรกคือกรอบที่คนลากเองว่าค่าอยู่ตรงไหน ซึ่งแม่นกว่าการเดาของ OCR/AI เสมอ
ถ้าชั้นหลังทับได้ ของที่เคยอ่านถูกจะกลายเป็นผิดโดยไม่มีใครรู้

มีชุดตรวจคุมข้อนี้ไว้ (`tests/read-layers.ts`)

## ไฟล์ที่เกี่ยวข้อง

| ไฟล์ | หน้าที่ |
| --- | --- |
| `src/lib/read-layers.ts` | กติกาการรวมผลจากหลายชั้น · รายการช่องสำคัญ |

ชั้น OCR กับ AI ต้องอยู่ฝั่งเซิร์ฟเวอร์ เพราะใช้กุญแจที่ส่งให้เบราว์เซอร์ไม่ได้

## เปิดใช้งาน

**ไม่ตั้งค่าอะไรเลยก็ใช้ได้** — ชั้น 1-2 ทำงานอยู่แล้ว
ชั้นที่ยังไม่ได้ตั้งค่าจะถูกข้ามไปเงียบ ๆ ไม่ทำให้พัง

> ขั้นตอนตั้งค่าแบบทีละขั้น (พร้อมวิธีแก้เมื่อติดปัญหา) อยู่ใน
> **[SETUP-OCR-AI.md](SETUP-OCR-AI.md)**

### ชั้น AI (แนะนำ — แม่น 100%)

```
ANTHROPIC_API_KEY=sk-ant-...
```

ขอที่ https://console.anthropic.com/settings/keys

### ชั้น OCR (ฟรี · เป็นตาข่ายรับท้าย)

```
GOOGLE_OAUTH_CLIENT_ID=
GOOGLE_OAUTH_CLIENT_SECRET=
GOOGLE_OAUTH_REFRESH_TOKEN=
```

ขอด้วย `npx tsx scripts/google-oauth.mts <CLIENT_ID> <CLIENT_SECRET>`
(ต้องมี OAuth client แบบ Desktop app + เปิด Google Drive API — ฟรี ไม่ต้องเปิด billing)

ตั้งไว้ก็ดี — ใช้ตอน AI ล่มหรือเครดิตหมด แต่ **ค่าที่ได้ต้องตรวจให้ละเอียดกว่าปกติ**

## กันค่าผิดจาก AI ยังไง

ชั้น AI ต่างจากชั้นอื่น — ชั้นอื่นอ่านไม่ออกก็คืนค่าว่าง
แต่ AI อาจ **เดาค่าที่ดูสมเหตุสมผลแต่ไม่มีในเอกสาร** ซึ่งอันตรายกว่ามาก

กันสองชั้น:

**1. สั่งในคำถาม** — ย้ำว่าหาไม่เจอให้ตอบค่าว่าง ห้ามเดา ห้ามเอาค่าช่องอื่นมาใส่แทน

**2. กรองค่าที่ตอบมาอีกที** (`sanitize()` ใน `read-ai.ts`) — ด่านสุดท้ายก่อนถึงฟอร์ม

| ช่อง | ทิ้งเมื่อ |
| --- | --- |
| เลขตู้ | ไม่เข้ารูป ISO 6346 (4 ตัวอักษร + 7 ตัวเลข) |
| เลขซีล | จำนวนไม่เท่าเลขตู้ (แปลว่าเรียงเพี้ยน จับคู่ผิดคันแน่) |
| น้ำหนัก / จำนวน | ไม่ใช่ตัวเลข หรือ ≤ 0 |
| เลข BL | สั้นกว่า 5 ตัว (แปลว่าอ่านผิดช่อง) |
| ETA | แปลงเป็นวันที่ไม่ได้ |

มีชุดตรวจยิงค่าผิดแบบต่าง ๆ เข้าไปดูว่าถูกทิ้งจริง (`tests/read-ai-sanitize.ts`)

**และค่าจากชั้น OCR/AI จะขึ้นข้อความเตือนให้ตรวจเป็นพิเศษ** พร้อมบอกค่าใช้จ่ายที่เกิดขึ้น

## วัดผลกับเอกสารจริง

ก่อนเปิดชั้นไหนในระบบจริง ควรวัดก่อนว่าคุ้มไหม:

```bash
npm run try:ocr -- ../../test/BL --drive --claude
```

บอกคะแนนรายใบ เทียบทุกวิธี และ**ค่าใช้จ่ายจริงต่อใบ**
รายละเอียดใน [TRY-OCR-AI.md](TRY-OCR-AI.md)
