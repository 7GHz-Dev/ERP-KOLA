# ทดลองวิธีใหม่สำหรับอ่าน AN / BL

เอกสารนี้บอกวิธีทดสอบว่า **Google Drive OCR** กับ **Claude API** อ่าน AN/BL
ได้ดีแค่ไหน เทียบกับวิธีที่ใช้อยู่ตอนนี้ — ก่อนตัดสินใจว่าจะเอาเข้าระบบจริงไหม

เครื่องมือคือ `scripts/try-ocr-ai.ts` **ไม่แตะฐานข้อมูล ไม่บันทึกอะไร**
อ่านแบบร่างจากฐานมาใช้เทียบอย่างเดียว

---

## ปัญหาที่พยายามแก้

วัดกับเอกสารจริง 9 ใบ (45 ช่องที่ตรวจเฉลยแล้ว) ด้วยระบบที่ใช้อยู่ตอนนี้:

| กลุ่ม | ผล | อธิบาย |
| --- | --- | --- |
| ใบ PDF ปกติ | **16/16 = 100%** | กรอบทำงานได้ดีมาก ไม่ต้องแก้อะไร |
| ใบสแกน (ภาพล้วน) | **0/29 = 0%** | ไม่มีข้อความให้อ่าน กรอบก็ช่วยไม่ได้ |
| รวม | 16/45 = 36% | |

**ช่องว่างทั้งหมดอยู่ที่ใบสแกน** ไม่ใช่ที่ความแม่นของกรอบ
วิธีใหม่จึงต้องพิสูจน์ตัวเองที่กลุ่มนี้เป็นหลัก

ใบสแกนที่ใช้ทดสอบ — `wanhai_bl_1` · `wanhai_bl_2` · `maersk_bl_1`
· `One_BL_2` · `Namsung_1`

## วิธีที่ 1 — Google Drive OCR

**จุดเด่น: ฟรี และโปรเจกต์นี้มีโค้ดอยู่แล้ว** (`src/lib/drive-ocr.ts` ใช้กับสลิปธนาคาร)
Drive แปลง PDF เป็น Google Doc พร้อม OCR ในขั้นตอนเดียว ส่งไฟล์เข้าไปตรง ๆ ได้เลย

**ข้อจำกัดที่ต้องรู้ก่อนทดสอบ** — OCR คืนมาแค่ "ข้อความ" **ไม่มีพิกัด**
ระบบกรอบจึงใช้กับผลของ OCR ไม่ได้ ต้องพึ่งตัวอ่าน regex ล้วน ๆ
เพดานความแม่นจึงเท่ากับตัวอ่าน regex ซึ่งต่ำกว่ากรอบพอสมควร

### ตั้งค่า (ทำครั้งเดียว)

> ขั้นตอนละเอียดพร้อมภาพรวมทุกหน้าจอ ดู **[SETUP-OCR-AI.md](SETUP-OCR-AI.md)**
> ข้างล่างนี้เป็นฉบับย่อ

1. สร้าง OAuth client แบบ **Desktop app** ที่ Google Cloud Console
   และเปิดใช้ **Google Drive API** ในโปรเจกต์เดียวกัน (ฟรี ไม่ต้องเปิด billing)
2. ขอ refresh token:
   ```bash
   cd v2
   npx tsx scripts/google-oauth.mts <CLIENT_ID> <CLIENT_SECRET>
   ```
3. เอาค่าที่ได้ใส่ `.env.local`:
   ```
   GOOGLE_OAUTH_CLIENT_ID=...
   GOOGLE_OAUTH_CLIENT_SECRET=...
   GOOGLE_OAUTH_REFRESH_TOKEN=...
   ```

### รัน

```bash
cd v2
npx tsx --tsconfig tsconfig.json scripts/try-ocr-ai.ts ../../test/BL --drive
```

## วิธีที่ 2 — Claude API

**จุดเด่น: อ่านได้ทั้งไฟล์สแกนและไฟล์ปกติ เข้าใจตารางและ layout**
ไม่ต้องลากกรอบ ไม่ต้องดูแล regex สายเรือใหม่เข้ามาก็อ่านได้ทันที

**ข้อควรระวัง** — AI อาจ "เดา" ค่าที่ไม่มีในเอกสาร
คำสั่งในสคริปต์สั่งไว้ชัดว่าหาไม่เจอให้ตอบค่าว่าง ห้ามเดา
แต่ต้องดูผลจริงว่าเชื่อฟังแค่ไหน — **ดูช่องที่ "ได้ค่าแต่ผิด" เป็นพิเศษ**
ค่าว่างไม่อันตราย แต่ค่าผิดที่ดูน่าเชื่ออันตรายมาก

### ตั้งค่า

ขอคีย์ที่ https://console.anthropic.com/settings/keys แล้วใส่ `.env.local`:

```
ANTHROPIC_API_KEY=sk-ant-...
```

### รัน

```bash
cd v2
npx tsx --tsconfig tsconfig.json scripts/try-ocr-ai.ts ../../test/BL --claude
```

สคริปต์รายงาน **ค่าใช้จ่ายจริงต่อใบ** จาก token ที่ใช้ และประมาณให้ว่า
ถ้าเดือนละ 200 ใบจะเป็นเงินเท่าไหร่

## อ่านผลยังไง

ดู 3 อย่างนี้ ตามลำดับความสำคัญ

**1. ใบสแกนได้กี่ช่อง** — คือเหตุผลทั้งหมดที่ทำเรื่องนี้
ถ้าวิธีใหม่ยังได้ 0 ก็ไม่ต้องไปต่อ

**2. ใบปกติแย่ลงไหม** — ตอนนี้ได้ 16/16 ถ้าวิธีใหม่ได้น้อยกว่านี้
แปลว่าต้องใช้แบบผสม คือใบปกติใช้กรอบเหมือนเดิม ใบสแกนค่อยเรียกวิธีใหม่
(ซึ่งเป็นสิ่งที่ควรทำอยู่แล้ว เพราะเร็วกว่าและไม่มีค่าใช้จ่าย)

**3. มีช่องไหน "ได้ค่าแต่ผิด" บ้าง** — อันตรายกว่าค่าว่าง
เพราะผู้ใช้กดบันทึกเร็วและมักไม่ทันสังเกต ถ้าเจอบ่อยต้องแก้คำสั่งหรือไม่ใช้วิธีนั้น

## ทางที่น่าจะลงเอย

ผลที่วัดได้บอกว่าใบปกติทำได้ 100% อยู่แล้ว จึงไม่มีเหตุผลต้องเปลี่ยน
สิ่งที่ควรทำคือ **ใช้แบบผสม**

```
อัปโหลดไฟล์
  ├─ pdf.js อ่านข้อความได้      → ใช้กรอบ + regex (เหมือนเดิม · ฟรี · เร็ว)
  └─ อ่านไม่ได้เลย (ไฟล์สแกน)  → เรียกวิธีใหม่
```

แบบนี้จ่ายเฉพาะใบสแกน ซึ่งเป็นส่วนน้อย และใบปกติยังเร็วเท่าเดิม

**แต่ต้องวัดก่อน** ตัวเลขจากการทดสอบจริงเท่านั้นที่บอกได้ว่าวิธีไหนคุ้ม

## เพิ่มใบทดสอบ

แก้ `ANSWERS` ใน `scripts/try-ocr-ai.ts` ใส่ชื่อไฟล์กับค่าที่ถูกต้อง
ช่องไหนยังไม่ได้ตรวจด้วยตา **อย่าใส่** — จะกลายเป็นคะแนนหลอก

```ts
'ชื่อไฟล์.pdf': {
  blNo: 'ค่าจริง', vessel: 'ชื่อเรือจริง',
},
```
