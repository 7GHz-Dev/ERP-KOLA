# ทำให้ตัวอ่าน AN / BL แม่นขึ้น

เอกสารนี้เขียนไว้ให้คนที่มาทำต่อ (คนหรือ AI) รู้ว่าต้องแก้ตรงไหนและวัดผลยังไง
หลักการเดียวที่ห้ามละเมิด: **เติมค่าผิดแย่กว่าปล่อยว่าง**
ผู้ใช้กดบันทึกเร็วและมักไม่ทันสังเกตค่าที่ระบบเติมให้ ค่าผิดจึงหลุดไปถึงจดหมายที่ยื่นสายเรือได้

---

## ไฟล์ที่เกี่ยวข้อง

| ไฟล์ | หน้าที่ |
| --- | --- |
| `src/lib/parse-arrival.ts` | อ่าน B/L, สายเรือ, ชื่อเรือ, เที่ยวเรือ, ETA, น้ำหนัก, ตู้, ซีล, ผู้ส่งออก |
| `src/lib/port-of-loading.ts` | อ่าน Port of Loading (ใช้ทั้งฝั่งเบราว์เซอร์และเซิร์ฟเวอร์) |
| `src/lib/match-shipper.ts` | จับชื่อผู้ส่งออกที่อ่านได้เข้ากับรายชื่อใน Master Data |
| `tests/parse-accuracy.ts` | สคริปต์วัดความแม่น |
| `tests/fixtures/arrival/*.txt` | ข้อความจากเอกสารจริง **ไม่ได้เก็บขึ้น git** (ดูหัวข้อถัดไป) |

## ชุดทดสอบไม่ได้อยู่ใน repo

repo นี้เป็น public ส่วนข้อความจาก AN/BL มีชื่อบริษัทซัพพลายเออร์และที่อยู่จริงของคู่ค้า
จึงใส่ `tests/fixtures/` ไว้ใน `.gitignore` — ต้องสร้างในเครื่องตัวเองก่อนใช้งาน

สร้างจากไฟล์ที่อยู่ในระบบจริง (ต้องมี `.env.local` ที่ต่อฐานข้อมูลได้):

```bash
# ดาวน์โหลดไฟล์ BL/AN ที่แนบกับงาน แล้วดึงข้อความออกเป็น .txt
# ใส่ไว้ที่ tests/fixtures/arrival/<ชื่อ>.txt
```

ถ้าไม่มีชุดทดสอบ สคริปต์วัดผลจะไม่มีไฟล์ให้อ่านและรายงานว่า 0 ใบ
**อย่า commit ไฟล์ในโฟลเดอร์นี้ขึ้น git ไม่ว่ากรณีใด**

## วิธีวัดผล

```bash
cd v2
npx tsx --tsconfig tsconfig.json tests/parse-accuracy.ts
```

รายงานมีสองส่วน

1. **อ่านได้กี่ใบ** — นับว่ามีค่าออกมาไหม ยังไม่ตัดสินว่าถูก ใช้ดูแนวโน้มกว้าง ๆ
2. **ค่าที่ตรวจด้วยตาแล้ว** — เทียบกับค่าจริงใน `EXPECTED` ส่วนนี้คือของจริง **ต้องผ่านครบเสมอ**

สคริปต์คืน exit code 1 เมื่อมีค่าไม่ตรง เอาไปต่อกับ CI ได้เลย

## ขั้นตอนเวลาจะทำให้แม่นขึ้น

**1. เพิ่มเอกสารที่อ่านไม่ได้เข้าไปในชุดทดสอบก่อน**

ดึงข้อความออกจาก PDF (ใช้ `extractPdfTextServer` ใน `port-of-loading.ts` หรือ pdfjs ตรง ๆ)
แล้ว **ปกปิดข้อมูลลูกค้าก่อนเสมอ** — ชื่อบริษัท ที่อยู่ เบอร์โทร อีเมล ชื่อคน เลขตัวถัง

ระวังตอนปกปิด: อย่าใช้ regex กว้างเกินจนกินข้อมูลที่ใช้ทดสอบ
เคยพลาดมาแล้วสองครั้ง — regex เบอร์โทรกินวันที่ ISO (`2026-06-01`) และ
regex ชื่อคนหลัง `ATTN:` กินชื่อเรือที่อยู่ถัดไป **รันสคริปต์วัดผลก่อนและหลังปกปิด ตัวเลขต้องเท่ากัน**

**2. ดูว่าเอกสารนั้นวางข้อความยังไงจริง ๆ**

```bash
python3 -c "
import re,io
t=re.sub(r'\s+',' ',io.open('tests/fixtures/arrival/<ไฟล์>.txt',encoding='utf-8').read())
i=t.upper().find('VESSEL')       # เปลี่ยนเป็นคำที่กำลังหา
print(repr(t[max(0,i-120):i+160]))"
```

อย่าเดารูปแบบเอง ให้ดูข้อความจริงเสมอ pdf.js ทำให้ข้อความเพี้ยนได้หลายแบบ

**3. แก้ pattern แล้วรันวัดผลใหม่**

ตัวเลข **ห้ามต่ำลง** ถ้าช่องไหนต่ำลงแปลว่าแก้ให้สายเรือหนึ่งแล้วอีกสายพัง
เกิดขึ้นบ่อยมาก ต้องรันทุกครั้ง

**4. ตรวจค่าที่ได้ด้วยตา แล้วใส่ลง `EXPECTED`**

การนับว่า "อ่านได้" ไม่พอ ต้องเปิดดูว่าค่าที่ได้ตรงกับในเอกสารจริงไหม
ใส่ลง `EXPECTED` แล้วรอบหน้าจะมีตาข่ายกันพลาดอัตโนมัติ

## กับดักที่เจอมาแล้ว

**pdf.js แทรกช่องว่างกลางคำ** — Maersk วางตัวอักษรห่างกันจนได้ `ARRIV AL NOTICE`,
`V OYAGE NO`, `TMA CO.,L TD` ตอนเทียบต้องยุบช่องว่างทิ้งก่อน (`match-shipper.ts` ตัดคำต่อท้ายสองรอบเพราะเรื่องนี้)

**ใบที่วางเป็นตาราง** — ONE เอาหัวช่องทุกช่องไปรวมไว้แถวเดียว ค่าจริงอยู่ห่างออกไปมาก
regex แบบ "ป้ายแล้วตามด้วยค่า" ใช้ไม่ได้ ตอนนี้เลือกปล่อยว่างดีกว่าเดา
ถ้าจะทำจริงต้องอ่านพิกัด x/y ของข้อความเพื่อจับคู่หัวตารางกับค่าที่อยู่ใต้ลงมา

**หยิบค่าแรกที่เจอ** — ใบที่มีรถหลายคันจะไล่น้ำหนักรายคันก่อนแล้วค่อยสรุปรวม
เคยได้ `1,690` แทนที่จะเป็น `16,350` ตอนนี้มองหาบรรทัด TOTAL ก่อน ไม่มีค่อยใช้ค่ามากสุด

**คำที่ดูเหมือนค่า** — เคยจับ `GROSS` มาเป็นเลขซีล และ `40SD96` (รหัสขนาดตู้) มาเป็นซีล
เลขซีลจริงต้องมีทั้งตัวอักษรและตัวเลขปนกัน และต้องไม่ใช่รูปแบบเลขตู้หรือรหัสขนาด

**จับซีลไม่ตรงตู้** — ฟอร์มจับคู่ซีลกับตู้ด้วยลำดับในรายการ
ห้ามใช้ `new Set()` หรือกรองค่าว่างทิ้ง เพราะลำดับจะเลื่อนแล้วซีลไปโผล่ผิดตู้
ตอนนี้คืนช่องว่างไว้ตรงตำแหน่งที่หาไม่เจอ
