# สร้างกรอบอ่านค่า AN / BL ให้ครบทุกสายเรือในครั้งเดียว

เอกสารนี้เขียนให้คนที่ต้องตั้งกรอบอ่านค่าของสายเรือหลาย ๆ สายพร้อมกัน
หลักการเดียวที่ห้ามละเมิด: **กรอบต้องมาจากพิกัดในไฟล์จริง ห้ามเดา**
กรอบที่เดาแล้ววางเหลื่อมจะดึงค่าผิดช่องมาใส่ฟอร์ม ซึ่งแย่กว่าไม่มีกรอบเลย
เพราะค่าจากกรอบ "มาก่อน" ตัวอ่านอัตโนมัติ — กรอบผิดจึงทับของเดิมที่เคยถูก

---

## ทำไมต้องมีสคริปต์ ทั้งที่มีหน้าลากกรอบอยู่แล้ว

หน้า `/master/parse-template` ให้ลากกรอบเองทีละช่อง แม่นและเห็นผลทันที
เหมาะกับการเพิ่มสายใหม่ทีละสาย หรือแก้กรอบที่เพี้ยนไปช่องเดียว

แต่ตอนตั้งระบบครั้งแรก มีสายเรือ 8 สาย แต่ละสายมีทั้ง BL และ AN คนละหน้าตา
รวม 14 แบบ ช่องละ ~10 กรอบ = ~140 กรอบ ซึ่งใช้เวลาทั้งวันและลากเหลื่อมได้ง่าย

`scripts/build-parse-templates.ts` ทำแทน — เราบอกแค่ว่า
"ค่าที่ถูกต้องของใบตัวอย่างนี้คืออะไร" แล้วมันไปหาเองว่าค่านั้นอยู่พิกัดไหนในไฟล์
แล้วคำนวณกรอบครอบให้ พิกัดจึงมาจากเอกสารจริงเสมอ

| ไฟล์ | หน้าที่ |
| --- | --- |
| `src/lib/auto-frame.ts` | หาพิกัดของค่าในไฟล์ แล้วคำนวณกรอบ |
| `scripts/build-parse-templates.ts` | นิยามค่าที่ถูกต้องของแต่ละแบบ + เขียนลง Master Data |
| `tests/auto-frame.ts` | ตรวจว่ากรอบที่สร้างวางตรงจริง |

## ต้องมีไฟล์ตัวอย่างก่อน

**สคริปต์นี้รันไม่ได้ถ้าไม่มีไฟล์ PDF ตัวอย่างในเครื่อง** — มันต้องเปิดไฟล์จริง
เพื่อดูว่าตัวอักษรอยู่พิกัดไหน ดูจากข้อความที่ copy มาอย่างเดียวไม่พอ

repo นี้ไม่เก็บเอกสารลูกค้า (`test/` อยู่ใน `.gitignore`) ต้องเอามาวางเองในเครื่อง

สร้างโฟลเดอร์แล้ววางไฟล์โดย **ตั้งชื่อให้ตรงกับช่อง `file` ใน `SPECS`**:

```
<โฟลเดอร์ที่เลือก>/
  wanhai_bl_1.pdf          Evergreen_waybill_1.pdf
  wanhai_an_1.pdf          Evergreen_an_1.pdf
  One_BL_2.pdf             OOCL_WAYBILL_1.pdf
  One_AN_1.pdf             OOCL_AN_1.pdf
  maersk_bl_1.pdf          Waybill_cnc_1.pdf
  maersk_1.pdf             cnc_1.pdf
  Namsung_1.pdf            Knot Global_1.pdf
```

ไฟล์ไหนไม่มี สคริปต์จะข้ามแบบนั้นไปแล้วบอกว่าข้าม ไม่ล้ม — ทยอยเพิ่มทีหลังได้

### ไฟล์สแกน (ภาพล้วน) ใช้ไม่ได้

**ถ้าใบไหนเป็น PDF สแกน จะลากกรอบไม่ได้เลย ไม่ว่าจะด้วยสคริปต์หรือด้วยมือ**
เพราะข้างในเป็นภาพ ไม่มีข้อความให้ pdf.js อ่าน — ตัวอ่านอัตโนมัติก็อ่านไม่ได้เช่นกัน
อาการคือทุกช่องขึ้น "หาไม่เจอ" พร้อมกันและได้ 0 กรอบ

เท่าที่ตรวจชุดตัวอย่างชุดแรก มี 3 ใบที่เป็นไฟล์สแกน — `wanhai_bl_1`,
`maersk_bl_1`, `Namsung_1` (และ `wanhai_bl_2`, `One_BL_2`)
ทางแก้คือ**ขอไฟล์ต้นฉบับที่สายเรือออกให้เป็น PDF จริง** ไม่ใช่ใบที่สแกนมา
แล้วรันสคริปต์ใหม่ — ระหว่างนี้ใบพวกนั้นยังต้องกรอกมือ

ตรวจว่าใบไหนเป็นไฟล์สแกนได้จากจำนวนช่องที่ "หาไม่เจอ" ในผลรัน
ถ้าไม่เจอทุกช่องพร้อมกัน แปลว่าเป็นไฟล์สแกน ไม่ใช่ค่าใน `SPECS` ผิด

## วิธีรัน

```bash
cd v2

# 1) ลองก่อน — ไม่แตะฐานข้อมูล แค่บอกว่าสร้างกรอบได้กี่ช่องและอ่านกลับได้อะไร
npx tsx --tsconfig tsconfig.json scripts/build-parse-templates.ts ./test/BL

# 2) เขียนลง Master Data จริง เมื่อผลข้างบนดูถูกต้องแล้ว
npx tsx --tsconfig tsconfig.json scripts/build-parse-templates.ts ./test/BL --write

# เก็บกรอบเป็นไฟล์ไว้ตรวจหรือย้ายเครื่อง (ไม่บังคับ)
npx tsx --tsconfig tsconfig.json scripts/build-parse-templates.ts ./test/BL --json frames.json
```

### อ่านผลที่ออกมา

```
WAN HAI — Bill of Lading  (3 หน้า)
  กรอบ 10 · ช่อง เลข BL, ชื่อ Shipper, ชื่อเรือ, ...
  อ่านกลับได้: เลข BL=011GX04250 · ชื่อเรือ=WAN HAI 278 · ตู้ 3 ตู้
  ⚠ หาไม่เจอ: น้ำหนักรวม ("16,900.000")
```

บรรทัด **อ่านกลับได้** สำคัญที่สุด — เป็นการเอากรอบที่เพิ่งสร้างไปอ่านไฟล์เดิมซ้ำ
ถ้าค่าที่ได้ตรงกับที่ควรเป็น แปลว่ากรอบวางถูกตำแหน่งจริง ไม่ใช่แค่สร้างสำเร็จ

บรรทัด **⚠ หาไม่เจอ** ไม่ใช่ความผิดพลาดเสมอไป มักเป็นเพราะ
ค่าใน `SPECS` สะกดไม่ตรงกับในไฟล์ (เช่นลูกน้ำคั่นหลักพัน หรือมีวรรคต่างกัน)
เปิดไฟล์ดูแล้วแก้ค่าใน `SPECS` ให้ตรง แล้วรันใหม่ — ช่องที่ยังหาไม่เจอ
จะไม่มีกรอบ และตกไปใช้ตัวอ่านอัตโนมัติตามเดิม ซึ่งไม่ได้แย่ลงกว่าก่อนมีสคริปต์

รันซ้ำได้ไม่จำกัด — แบบร่างชื่อเดียวกันจะถูก**เขียนทับ** ไม่สร้างซ้ำ

## เพิ่มสายเรือใหม่

แก้ `SPECS` ใน `scripts/build-parse-templates.ts` เพิ่มก้อนใหม่:

```ts
{
  file: 'ชื่อไฟล์ตัวอย่าง',        // ไม่ต้องใส่ .pdf
  name: 'ชื่อสาย — ชนิดเอกสาร',   // ชื่อนี้ใช้เทียบว่าจะทับของเดิมไหม
  match: ['คำที่ต้องเจอ', 'อีกคำ'], // ต้องเจอครบทุกคำจึงถือว่าเป็นแบบนี้
  values: { blNo: 'ค่าจริงในใบนี้', vessel: 'ชื่อเรือจริง' },
  lists: { containers: ['ตู้1', 'ตู้2'], seals: ['ซีล1', 'ซีล2'] },
}
```

**คำใน `match` ต้องเจาะจงพอ** — ถ้าสั้นหรือกว้างไป จะไปตรงกับเอกสารของสายอื่นด้วย
แล้วจับแบบผิด สคริปต์ตรวจให้ระดับหนึ่งว่าคำที่ใส่ตรงกับไฟล์ตัวอย่างของตัวเองจริงไหม
แต่ไม่ได้ตรวจว่ามันไปตรงกับใบของสายอื่นด้วยหรือเปล่า

### ค่าใน `values` ต้องยาวพอ (อย่างน้อย 3 ตัวอักษร/ตัวเลข)

ค่าที่สั้นกว่านั้นถูกปฏิเสธ ไม่เอามาสร้างกรอบ เพราะเลขสองหลักอย่าง `33`
โผล่ได้ทั่วหน้ากระดาษ — เลขหน้า ปีรถ ลำดับรายการ น้ำหนัก ตรงได้หมด
ตัวแรกที่เจอจึงมักไม่ใช่ช่องที่เราต้องการ แล้วได้กรอบที่วางผิดที่อย่างมั่นใจ

ช่องที่ค่าสั้นตามธรรมชาติ เช่นจำนวนหน่วย ให้ใส่ข้อความที่ยาวพอจะเจาะจงแทน
โดยเอาหน่วยที่อยู่ติดกันมาด้วย ตัวอ่านตัดหน่วยออกให้เองอยู่แล้ว:

```ts
unitAmount: '13 UNITS',   // ไม่ใช่ '13'
unitAmount: '39 UNT',     // WAN HAI AN เขียนย่อแบบนี้
```

### ค่าต้องตรงกับ "ชิ้นข้อความ" ในไฟล์ ไม่ใช่ตรงกับที่ตาเห็น

สคริปต์จับเฉพาะชิ้นที่ **ตรงเป๊ะทั้งชิ้น** เท่านั้น เพราะการยอมรับชิ้นที่มีค่า
อยู่ข้างในทำให้ได้ค่าผิดบ่อยมาก (หา `JAN TRADING CO.` แล้วไปได้อีเมล
`JAN-JAPAN@JANTRADINGCO.JP` มาแทน)

pdf.js หั่นข้อความตามการจัดระยะในไฟล์ ซึ่งมักไม่ตรงกับช่องที่ตาเห็น เช่น

| ตาเห็นเป็น | ในไฟล์เก็บเป็นชิ้นเดียว | ต้องใส่ใน `SPECS` ว่า |
| --- | --- | --- |
| ชื่อเรือ / เที่ยวเรือ คนละช่อง | `[EVER BLINK 1207-084A]` | `vessel: 'EVER BLINK 1207-084A'` |
| น้ำหนัก `49,850` | `[49850KGS]` | `grossWeight: '49850KGS'` |
| B/L No `EGLV0606...` | `[: EGLV060600120711]` | `blNo: ': EGLV060600120711'` |

ใส่ให้ตรงกับในไฟล์ได้เลย ไม่ต้องกลัวว่าป้ายหรือหน่วยจะติดมา —
ตัวอ่านตัดป้าย หน่วย และเครื่องหมายคั่นหน้าค่าออกให้อยู่แล้วตอนอ่านจริง

**วิธีดูว่าในไฟล์เก็บเป็นชิ้นอะไร** ให้เขียนสคริปต์สั้น ๆ พิมพ์ชิ้นที่มีคำนั้นออกมา
(ดูตัวอย่างใน `tests/auto-frame.ts`) แล้วก๊อปข้อความในวงเล็บเหลี่ยมไปใส่ตรง ๆ

### โหมดหน้า

เอกสารสายเดียวกันมีจำนวนหน้าไม่เท่ากัน ขึ้นกับว่ามีสินค้ากี่รายการ
ผูกกรอบกับเลขหน้าตายตัวอย่างเดียวจึงไม่พอ ใช้ `pageMode` เมื่อจำเป็น:

```ts
pageMode: {
  grossWeight: 'last',   // ยอดรวมท้ายใบ ที่เลขหน้าไม่แน่นอน
  containers: 'every',   // เลขตู้ที่ไล่ต่อกันข้ามหน้า
}
```

ไม่ระบุ = ใช้หน้าที่เจอค่านั้นจริงในไฟล์ตัวอย่าง เหมาะกับค่าที่อยู่หน้าเดิมเสมอ
เช่นเลข BL ชื่อเรือ ETA

## ตรวจว่ากรอบยังวางตรง

```bash
cd v2
npx tsx --tsconfig tsconfig.json tests/auto-frame.ts

# ถ้าไฟล์ตัวอย่างอยู่ที่อื่น
SAMPLE_DIR=/path/to/pdfs npx tsx --tsconfig tsconfig.json tests/auto-frame.ts
```

ไม่มีไฟล์ตัวอย่างในเครื่อง = ข้ามไปเฉย ๆ ไม่ถือว่าไม่ผ่าน

เทสต์นี้กันเรื่องที่พลาดง่ายที่สุดคือ **กรอบดูดป้ายของช่องเข้ามา**
เอกสารเดินเรือวางบรรทัดชิดกัน ป้ายอยู่เหนือค่าแค่บรรทัดเดียว
วัดจาก MAERSK จริงแล้ว เผื่อกรอบแนวตั้ง `0.006` ได้ชื่อ Shipper เป็น
`"NOTIFY PARTY (COMPLETE NAME AND ADDRESS) KOLA SHIPPING CO.,LTD."`
ซึ่งเอาไปจับกับ Master Data ไม่ได้เลย ส่วน `0.002` ได้ชื่อล้วน

ค่าเผื่อจึงอยู่ที่ `PADDING` ใน `src/lib/auto-frame.ts` — **เผื่อแนวนอนได้เยอะ**
(ค่าจริงยาวไม่เท่ากันแต่ละใบ) แต่ **เผื่อแนวตั้งต้องน้อย** ถ้าขยับขึ้นเทสต์จะฟ้อง

## ใบอื่นที่ไม่ใช่ใบตัวอย่าง — กรอบครอบคลุมแค่ไหน

กรอบสร้างจากใบเดียว แต่ต้องใช้กับทุกใบของสายนั้น ซึ่งยาวไม่เท่ากันและค่าไม่เท่ากัน
เรื่องนี้ทดสอบแล้วกับใบจริงคนละ shipment 9 ใบ (1–7 หน้า) ได้ผลดังนี้

### ช่องหัวกระดาษ — ปลอดภัย ไม่ต้องทำอะไร

เลข BL · ชื่อเรือ · เที่ยวเรือ · ETA · Port of Loading · ชื่อ Shipper · น้ำหนัก
สายเรือใช้ฟอร์มเดียวกันทุกใบ ช่องพวกนี้จึงอยู่ตำแหน่งเดิมเสมอ
ต่อให้เนื้อหายาวกว่าหรือสั้นกว่า หัวกระดาษไม่ขยับ

ทดสอบแล้วอ่านถูกทุกใบ เช่น MAERSK ใบที่ไม่เคยเห็นได้
`MARTIN SCHULTE · 628S · 274158996` ครบถ้วน

### ช่องในตาราง (เลขตู้ · เลขซีล) — เลื่อนได้ ระบบยืดกรอบให้แล้ว

ตารางตู้อยู่ใต้ส่วนรายละเอียดสินค้า ซึ่งยาวไม่เท่ากันตามจำนวนรถ
วัดจาก EVERGREEN Arrival Notice จริง 4 ใบ แถวตู้อยู่ที่

```
top = 0.656 · 0.684 · 0.741 · 0.884      เลื่อนลงได้ถึง 23% ของความสูงหน้า
```

กรอบที่ครอบพอดีใบตัวอย่างจึงพลาดใบอื่นเกือบหมด
`stretchForDrift()` ใน `auto-frame.ts` จึง**ยืดกรอบของสองช่องนี้**
ขึ้นบน 10% ลงล่าง 26% ของหน้า ให้คลุมทั้งช่วงที่ตารางเลื่อนไปได้

ยืดแล้วไม่เสี่ยง เพราะตัวอ่านคัดด้วยรูปแบบอีกชั้น — เลขตู้ต้องเข้ารูป ISO 6346
(4 ตัวอักษร + 7 ตัวเลข) และเลขซีลต้องมีทั้งตัวอักษรและตัวเลข
ข้อความอื่นที่กวาดติดมาถูกทิ้งหมด

**ยืดเฉพาะสองช่องนี้เท่านั้น** ช่องหัวกระดาษยืดไม่ได้ เพราะป้ายกับค่าช่องอื่น
อยู่ชิดกันแค่บรรทัดเดียว ยืดแล้วจะดูดของข้างเคียงเข้ามา (มีเทสต์กันไว้)

### ถ้าเจอใบที่ยังอ่านไม่ได้

1. เปิด `/master/parse-template` เลือกแบบนั้น แล้วเปิดใบที่อ่านไม่ได้
2. ดูว่ากรอบไหนหลุด แล้วลากใหม่ให้กว้างขึ้นคลุมทั้งสองใบ
3. ไม่ต้องกลับมารันสคริปต์ — แก้ในหน้านั้นมีผลทันที

ถ้าเอกสารต่างกันมากจนกรอบเดียวคลุมไม่ไหว ให้**แยกเป็นคนละแบบ**
โดยใส่คำที่ใช้จับแบบให้ต่างกัน ดีกว่าฝืนใช้กรอบเดียวแล้วได้ค่าผิดทั้งสองใบ

## หลังรันเสร็จ

1. เปิด `/master/parse-template` ดูว่าแบบร่างขึ้นครบ และช่องที่กำหนดไว้ถูกต้อง
2. กดเข้าไปในแบบใดแบบหนึ่ง เปิดไฟล์ตัวอย่างแล้วดูว่ากรอบวางตรงตามที่เห็นจริง
3. ลองอัปโหลดใบจริงของสายนั้นที่ **ไม่ใช่ใบตัวอย่าง** แล้วดูว่าเติมค่าถูกไหม
   — ข้อนี้สำคัญ เพราะกรอบสร้างจากใบเดียว แต่ต้องใช้ได้กับทุกใบของสายนั้น
4. ช่องไหนเพี้ยน แก้ด้วยการลากกรอบใหม่ในหน้านั้นได้เลย ไม่ต้องกลับมารันสคริปต์
