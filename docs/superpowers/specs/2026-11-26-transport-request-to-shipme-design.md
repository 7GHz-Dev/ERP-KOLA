# Transport Request + ใบขน / E-Office → ERP SHIPME (เมนูชั่วคราวของ MAY)

วันที่ 26 พ.ย. 2569 · สถานะ: รออนุมัติ

## ทำไม

ฝั่ง KOLA ยังส่งแพลนลากตู้และเอกสารตรวจปล่อย (ใบขน · E-Office) ให้ SHIPME เองไม่ได้
ระหว่างนี้ MAY ได้รายการงานเป็นตาราง Transport Request (รูปจากชีตของลูกค้า MSFZ)
และได้ไฟล์ใบขน / E-Office เป็น PDF แยกกัน

เมนูชั่วคราวสองเมนูใน KOLA (ส่วน MAY) พาข้อมูลชุดนี้เข้า SHIPME
ชิปปิ้งจะได้เห็นงานในตารางขนส่งกับแพลนงาน และรู้ว่าเอกสารของแต่ละ BL พร้อมหรือยัง

## เป้าหมาย

1. MAY นำเข้า Transport Request จากรูป (หรือวางข้อความจากชีต)
   - ระบบจับคู่แต่ละแถวกับงานใน KOLA แล้วแสดงตัวอย่างแบบตารางขนส่ง SHIPME
   - MAY ตรวจและแก้ได้ แล้วกด "ส่งให้ SHIPME"
2. งานที่ส่งไปแล้วขึ้นในตารางขนส่ง (`transport_records`) และในแพลนงานของวัน TRANSPORT นั้น
3. แพลนงานแสดงความพร้อมเอกสาร 3 อย่างต่อ BL
   - **DO**: ANN ส่งแลก DO แล้ว (`jobs.do_exchanged_at` ใน KOLA)
   - **ใบขน**: มีไฟล์ใบขนที่ส่งมาแล้ว
   - **E-Office**: มีไฟล์ E-Office ที่ส่งมาแล้ว
4. MAY อัปไฟล์ใบขนและ E-Office หลายไฟล์พร้อมกัน ระบบจับคู่กับ BL ให้เอง
   - อัปก่อนหรือหลังส่งตารางก็ได้

## ไม่ทำ

- ไม่แนบไฟล์ใบขน / E-Office เข้างานใน KOLA (ผู้ใช้เลือกแล้ว) — KOLA ไม่เก็บอะไรเลย
- ไม่สร้างแถวแพลนแบบ `source = KOLA` (แถวนั้นสงวนไว้ให้ระบบแพลนลากตู้ตัวจริงของ KOLA)
- ไม่แตะขั้นตอนแลก DO ของ ANN

## ห้ามเกิด

- ห้ามส่งงานซ้ำเป็นสองแถวใน SHIPME ไม่ว่าส่งจาก KOLA หรือนำเข้าจากปุ่มเดิมในแพลนงานของ SHIPME
- ห้ามเปลี่ยนข้อมูลในฐานของ KOLA
- ห้ามให้สถานะ DO ค้างผิด
  - เมื่อถาม KOLA ไม่ได้ ให้ขึ้นว่า "ตรวจไม่ได้"
  - ห้ามขึ้น "ไม่พร้อม" หรือ "พร้อม" แทน

## วิธีที่เลือก (Approaches)

| แบบ | ข้อมูลตาราง + ไฟล์ | สถานะ DO | ข้อเสีย |
|---|---|---|---|
| **1 (เลือก)** | KOLA ส่งไปเก็บที่ SHIPME | SHIPME ถาม KOLA ทุกครั้งที่เปิดแพลน | KOLA ล่ม → ช่อง DO ขึ้น "ตรวจไม่ได้" |
| 2 | เหมือนแบบ 1 | KOLA ส่งไปบอกทุกครั้งที่ ANN แลก DO | ต้องแก้ขั้นตอน ANN · ส่งพลาดครั้งเดียวสถานะค้างผิด |
| 3 | เมนูอัปไฟล์อยู่ใน SHIPME | — | จับคู่ใบขน→BL ไม่ได้ (เลขใบขนอยู่ใน KOLA) · MAY ต้องสลับระบบ |

ผู้ใช้เลือกแบบ 1 เพราะเป็นของชั่วคราว ไม่แตะขั้นตอนของ ANN และสถานะไม่ค้างผิด

## ภาพรวม

```
KOLA (MAY)                                   SHIPME
──────────                                   ──────
[เมนู 1] รูป / ข้อความ Transport Request
   └ AI อ่านรูป → แถว
   └ จับคู่ BL กับงาน KOLA
   └ ตัวอย่างแบบตารางขนส่ง (แก้ได้)
   └ ส่งให้ SHIPME ───── kolaTransportPush ──▶ transport_records (BL + วันที่ TRANSPORT)
                                               แพลนงานของวันนั้นเสนอแถวเหล่านี้

[เมนู 2] อัปใบขน / E-Office หลายไฟล์
   └ จับคู่ไฟล์ → BL
   └ ขอ URL อัป ──────── kolaDocUploadUrl ───▶ Supabase Storage ของ SHIPME
   └ เบราว์เซอร์อัปไฟล์ตรงเข้า Storage ของ SHIPME
   └ แจ้งว่าอัปเสร็จ ──── kolaDocRegister ───▶ transport_docs (BL · ประเภท · ไฟล์)

                     ◀── GET /api/shipme/doc-status ── แพลนงานเปิดวันไหน ถาม DO ของ BL วันนั้น
```

## เมนู 1 — นำเข้า Transport Request (KOLA · MAY)

เส้นทาง `/may/transport-request` · เมนู "ส่ง Transport Request → SHIPME (ชั่วคราว)"

**รับข้อมูลเข้า**
- รูป (png/jpg วางจากคลิปบอร์ดหรือเลือกไฟล์ ได้หลายรูป)
  - ส่งให้ AI อ่าน ใช้ ANTHROPIC_API_KEY และรุ่นเดียวกับ `src/lib/read-ai.ts`
  - คำสั่งให้ตอบ JSON ต่อแถว: ETA · ประเภท · TRANSPORT · SHIPPER · CON · BILL OF LADING · CONTAINER NO. · SHIPLINE · VESSEL · PORT
  - หาค่าไม่เจอให้ตอบว่าง ห้ามเดา และตรวจรูปแบบของค่าที่ได้ซ้ำอีกชั้นตามแนวของ read-ai
- วางข้อความที่ Copy จาก Google Sheet / Excel (แท็บคั่น หาคอลัมน์จากหัวตาราง)
  - ไม่เสียค่า AI และแม่นกว่า

**วันที่**
- วันที่ของงานใน SHIPME = คอลัมน์ **TRANSPORT**
- คอลัมน์ ETA ใช้แสดงและตรวจเทียบกับ ETA ในงาน KOLA เท่านั้น

**จับคู่กับงาน KOLA**
- จับด้วยเลข BL ที่ตัดช่องว่างแล้วเป็นตัวพิมพ์ใหญ่
- BL รูปแบบ `KG1042026-74915(AMP0574862)` ลองทั้งส่วนนอกและส่วนในวงเล็บ
- แถวที่จับคู่ได้ ใช้ BL และเลขตู้จาก KOLA เป็นหลัก เพราะ AI อาจอ่านตัวอักษรผิด
  - ค่าที่อ่านได้ไม่ตรงกับ KOLA ขึ้นป้ายเตือนในช่องนั้น เช่น "รูป: TCNU313577 · KOLA: TCNU3135577"
  - เตือนเมื่อ CON ไม่ตรงจำนวนตู้
- แถวที่จับคู่ไม่ได้ยังส่งได้ ใช้ค่าตามรูป และขึ้นป้าย "ไม่พบใน KOLA"

**ตัวอย่างก่อนส่ง**
- หน้าตาแบบตารางขนส่ง SHIPME (รูปที่ 2): #, TRANSPORT, ชิปเปอร์, VESSEL (สายเรือ), เลข BL, CONTAINER NO. (เรียงบรรทัด), จำนวนตู้
- ต่อท้ายด้วยคอลัมน์สถานะ: จับคู่ KOLA · ใหม่/อัปเดตใน SHIPME · คำเตือน · DO แลกแล้ว
- แก้ช่องในตารางได้ก่อนส่ง และลบแถวได้
- กด "ตรวจกับ SHIPME" แล้วจะได้สถานะ ใหม่/อัปเดต และชิปปิ้งประจำท่าจาก SHIPME (preview แบบไม่บันทึก)

**ส่งให้ SHIPME**
- ปุ่ม "ส่งให้ SHIPME" ส่งเฉพาะแถวที่ไม่มีข้อผิดพลาด
- แสดงผล: ใหม่ n · อัปเดต n · ผิดพลาด n
- ส่งซ้ำ BL + วันที่เดิม = อัปเดตแถวเดิม

**แหล่ง (source)**
- ค่าเริ่มต้น MAESOT FREEZONE (คอลัมน์ "ประเภท" = MSFZ…)
- เลือก TRANSIT ได้ที่หัวหน้า

## เมนู 2 — อัปใบขน / E-Office (KOLA · MAY)

เส้นทาง `/may/transport-docs` · เมนู "อัปใบขน / E-Office → SHIPME (ชั่วคราว)"

**เลือกไฟล์**
- ลากวางหรือเลือกไฟล์ PDF ได้หลายไฟล์พร้อมกัน ปนกันได้ทั้งสองประเภท

**แยกประเภทและจับคู่ BL** (ทำทีละไฟล์ ตามลำดับนี้)
1. ชื่อไฟล์มีเลขใบขนรูปแบบ `A0310691002615`
   - ถือเป็น **ใบขน**
   - หา BL จาก `customs_entries.declaration_no` ใน KOLA โดยเทียบแบบตัดขีดออก
2. ชื่อไฟล์มีเลข BL ที่ตรงกับงาน KOLA หรือแถวในตารางขนส่ง และมี `E-` + ตัวเลข (เช่น `AMP0572751A E-744810.pdf`)
   - ถือเป็น **E-Office**
3. ไม่เข้าข้อ 1–2
   - อ่าน text layer ของ PDF (ไม่ใช้ AI) หาเลขใบตราส่งในวงเล็บหลัง "ใบตราส่งเลขที่"
   - หาเลขใบขนรูปแบบ `A0xx-x-xxxx-xxxxx` ด้วย
4. ยังไม่ได้
   - ขึ้นช่องให้เลือก BL และประเภทเอง (ค้น BL จากงาน KOLA)

**แสดงผลก่อนอัป**
- ตารางไฟล์: ชื่อไฟล์ · ประเภท (เปลี่ยนได้) · BL ที่จับได้ (เปลี่ยนได้) · วิธีที่จับได้ · DO แลกแล้วหรือยัง

**อัปโหลด**
- กดอัป ไฟล์ไปตรงจากเบราว์เซอร์เข้า Storage ของ SHIPME ผ่าน signed upload URL
  - ไม่ผ่าน server ของ KOLA เพราะไฟล์สแกนอาจใหญ่เกินเพดาน 4.5MB ของ Vercel
- เพดานต่อไฟล์ 20MB
- BL + ประเภทเดิมอัปซ้ำ = ไฟล์ใหม่เป็นไฟล์ปัจจุบัน ไฟล์เก่ายังเก็บไว้ (ดูย้อนได้)

**รายการล่าสุด**
- ใต้ฟอร์มมีรายการไฟล์ที่ส่งไปแล้ว 50 รายการล่าสุด ข้อมูลจาก SHIPME (ดู/ลบได้)

## ฝั่ง SHIPME

**ตารางใหม่ `transport_docs`** (migration 0024 + RLS)

| คอลัมน์ | ความหมาย |
|---|---|
| `id` | |
| `bl` | |
| `bl_key` | |
| `kind` | `DECL` \| `EOFFICE` |
| `file_name` | |
| `storage_key` | |
| `size` | |
| `mime` | |
| `current` | boolean |
| `kola_job_id` | |
| `declaration_no` | |
| `uploaded_by` | ชื่อ MAY ใน KOLA |
| `uploaded_at` | |

- index ที่ (`bl_key`, `kind`, `current`)
- ไม่ผูกกับ `transport_records` เพราะไฟล์มาก่อนแถวได้ จับคู่กันด้วย `bl_key` ตอนแสดง

**action ใหม่ใน `/api`** (ยืนยันตัวด้วย `KOLA_SYNC_TOKEN` แบบเดียวกับ `kola-plans.ts`)

| action | ทำอะไร |
|---|---|
| `kolaTransportPush` | รับแถว + `commit` true/false ใช้ตรรกะเดียวกับ `importTransportRequest` (แยกฟังก์ชันกลางออกมาใช้ร่วมกัน) · `importedFrom = 'kola'` · `createdBy = 'kola:<ชื่อ MAY>'` |
| `kolaDocUploadUrl` | รับ bl, kind, fileName, size → คืน signed upload URL + storageKey |
| `kolaDocRegister` | รับ storageKey + ข้อมูลไฟล์ → ตรวจว่าไฟล์มีจริงใน Storage → บันทึกแถว ตั้งไฟล์เดิมของ BL+kind เป็น `current = false` |
| `kolaDocList` | 50 รายการล่าสุด (เมนู 2) |
| `kolaDocDelete` | ลบไฟล์ (ตั้งไฟล์ก่อนหน้าเป็นปัจจุบันแทน) |

**แพลนงาน (`planLoad`)**
- `transportRowsFor(date)` ดึงจาก `transport_records` ของวันนั้นด้วย โดยแตก `containers_json` เป็นแถวละตู้
- รวมกับแถวจากชีต ตัดซ้ำด้วย BL + เลขตู้ตามกติกาเดิม
- ผู้จัดการวางแพลน แนบไฟล์คนขับ และ Confirm ตามปกติ
- แถวของแพลนเพิ่มป้ายเอกสาร 3 ช่องต่อ BL
  - **DO** ✓ / ✗ / ? (ตรวจไม่ได้)
  - **ใบขน** ✓ ลิงก์เปิดไฟล์ / ✗
  - **E-Office** ✓ ลิงก์เปิดไฟล์ / ✗
- ไฟล์เปิดผ่าน signed URL อายุสั้นของ SHIPME (แบบเดียวกับไฟล์อื่นในระบบ)

**หน้างานปล่อยของชิปปิ้ง (`myReleaseJobs`)**
- แสดงป้าย 3 ช่องเดียวกันและเปิดไฟล์ได้ เพราะชิปปิ้งต้องใช้เอกสารหน้างาน

**ตารางขนส่ง**
- ไม่เพิ่มคอลัมน์ (ตารางนั้นเป็นเรื่องค่าใช้จ่าย) แถวจาก KOLA ขึ้นตามปกติจาก `transport_records`

**ถามสถานะ DO**
- SHIPME เรียก `GET <โดเมน KOLA ของ KOLA_SPECIALS_URL>/api/shipme/doc-status?bl=...` (หลาย BL)
- ใช้ `Authorization: Bearer KOLA_SPECIALS_KEY` (คีย์เดิมที่ใช้ส่งค่าพิเศษ)
- timeout 4 วินาที ล้มเหลว = ทุก BL เป็น "ตรวจไม่ได้"

## ฝั่ง KOLA — endpoint ใหม่

`GET /api/shipme/doc-status?bl=A&bl=B…` (ยืนยันด้วย `shipmeAuthorized` เดิม · สูงสุด 300 BL)

```json
{ "ok": true, "items": { "<blKey>": { "found": true, "jobNo": "...", "doExchangedAt": "ISO|null" } } }
```

- จับคู่ BL ด้วยกติกาเดียวกับเมนู 1 รวมกรณีวงเล็บ
- ไม่พบ BL = `found: false` (แพลนขึ้น "ไม่พบใน KOLA")

## ค่าที่ต้องตั้ง

| ที่ไหน | ตัวแปร | ค่า |
|---|---|---|
| KOLA | `SHIPME_API_URL` | `https://<โดเมน SHIPME>/api` |
| KOLA | `SHIPME_SYNC_TOKEN` | = `KOLA_SYNC_TOKEN` ของ SHIPME |
| SHIPME | `KOLA_SYNC_TOKEN` | สุ่มใหม่ถ้ายังไม่มี |
| SHIPME | — | ใช้ `KOLA_SPECIALS_KEY` และโดเมน KOLA ชุดเดียวกับที่ส่งค่าพิเศษอยู่แล้ว (`KOLA_SPECIALS_URL` / ค่าเริ่มต้น) |

- ตัวแปรว่าง = เมนูใน KOLA ขึ้นว่า "ยังไม่ได้ตั้งค่าการเชื่อม SHIPME" ไม่ส่งอะไรออกไป
- ระบบทดสอบ erp-kola-test ไม่ตั้งค่าเหล่านี้ จึงไม่ยิงเข้า SHIPME ตัวจริง

## ฐานข้อมูล

- KOLA: ไม่มี migration
- SHIPME: migration 0024 (`transport_docs`) รันกับฐานจริงก่อน deploy SHIPME

## ถอดออกเมื่อ KOLA พร้อม

- **KOLA:** ลบสองหน้า สองเมนู และ client ที่เรียก SHIPME (`src/lib/shipme-client.ts`) โดย endpoint `doc-status` เก็บไว้ใช้ต่อ
- **SHIPME:** action `kola*` ของเมนูนี้เก็บไว้ได้ ตัวจริงของ KOLA จะส่งไฟล์ผ่าน action เดิมนี้

## เรื่องที่ผู้สร้างตัดสินใจเอง (ผมตัดสินใจไว้แล้ว แก้ได้)

- วันที่ใช้คอลัมน์ TRANSPORT ไม่ใช่ ETA
- แถวที่จับคู่ได้ใช้ BL/ตู้จาก KOLA เป็นหลัก
- ป้ายเอกสารขึ้นทั้งหน้าแพลนของผู้จัดการและหน้างานปล่อยของชิปปิ้ง
- ไม่ใช้ AI กับไฟล์ PDF (ชื่อไฟล์ + text layer พอ) · ใช้ AI กับรูปตาราง Transport Request เท่านั้น
- เพดาน 20MB ต่อไฟล์ · เก็บไฟล์เก่าเมื่ออัปทับ
- หน้าตาเมนูทั้งสองใช้คอมโพเนนต์ตารางและปุ่มเดิมของ KOLA ส่วนตัวอย่างใช้สีหัวตารางแบบตารางขนส่ง SHIPME
